# 🕌 بوت أسئلة المسجد عبر واتساب — Masjid WhatsApp Q&A Bot

بوت يستقبل أسئلة المصلّين على **واتساب**، يقرأ السؤال، يبحث عن الإجابة في **ملفٍ تُحدِّده أنت**،
ثم يردّ **بالعربية** تلقائيًا.

**التقنيات:** Baileys (واتساب) + n8n (التدفّق) + **DeepSeek / Gemini عبر مفتاح API** (الذكاء الاصطناعي).

> يمكنك أيضًا تشغيله **محليًا بلا إنترنت** عبر Ollama على الـ Mac mini M4 — انظر «بديل بلا إنترنت» في الأسفل.

---

## كيف يعمل؟ (المخطّط)

```
  المصلّي على واتساب
        │  (1) يرسل سؤالًا بالعربية
        ▼
 ┌─────────────────────┐     (2) Webhook      ┌──────────────────────────────┐
 │  Baileys Bridge     │ ───────────────────► │            n8n               │
 │  (baileys-bridge/)  │                      │  • يقرأ ملف المعرفة          │
 │   واتساب ↔ HTTP     │ ◄─────────────────── │  • يبني السؤال + المصدر       │
 └─────────────────────┘    (5) POST /send    │  • يسأل النموذج عبر API       │
        │                                      └──────────────┬───────────────┘
        │  (6) يرسل الإجابة                                    │ (3) سؤال + مصدر
        ▼                                                      ▼
  المصلّي على واتساب                              ┌──────────────────────────┐
                                                   │  DeepSeek API  أو        │
                                      (4) إجابة ◄──│  Gemini API  (عربي)      │
                                                   └──────────────────────────┘
```

1. المصلّي يرسل سؤالًا على رقم واتساب المسجد.
2. جسر Baileys يحوّل الرسالة إلى n8n عبر Webhook.
3. n8n يقرأ ملف `knowledge.md` ويبني الطلب (السؤال + محتوى الملف كمصدر).
4. النموذج (DeepSeek أو Gemini عبر API) يُولّد الإجابة بالعربية **اعتمادًا على الملف فقط**.
5. n8n يرسل الإجابة إلى جسر Baileys عبر `POST /send`.
6. الجسر يرسلها إلى المصلّي على واتساب.

## 🧠 DeepSeek أم Gemini؟ (وتصحيح مهم)

> **تصحيح لما قلته سابقًا:** كان تحفّظي على DeepSeek يخصّ **النسخة المحلّية الصغيرة المقطّرة** فقط.
> أمّا **DeepSeek عبر الـ API فهو النموذج الكامل V3** — قويّ وسريع وعربيته ممتازة وسعره زهيد. اختيار رائع. ✅

النموذجان مُعدّان وجاهزان في التدفّق، والتبديل بينهما **بنقرة** (انظر «تبديل النموذج»):

| النموذج | الاسم في n8n | العربية | السعر | ملاحظات |
|---|---|---|---|---|
| **DeepSeek** (الافتراضي) | `deepseek-chat` | ⭐⭐⭐⭐⭐ | رخيص جدًا | النموذج الكامل V3 عبر API. سريع ودقيق. |
| **Gemini** (بديل) | `models/gemini-2.0-flash` | ⭐⭐⭐⭐⭐ | **به طبقة مجانية** | ممتاز للعربية، وغالبًا **مجاني** لحجم مسجد. |

> ⚠️ لا تستخدم `deepseek-reasoner` لهذا البوت — فهو نموذج «تفكير» مُطوّل وبطيء وغير مناسب لردود واتساب القصيرة.
> استخدم `deepseek-chat`.

**التكلفة لمسجد؟ شبه معدومة.** حجم الأسئلة قليل، و Gemini له طبقة مجانية سخيّة، و DeepSeek من أرخص الواجهات.

> **«gama4»:** فهمتها على أنها **Google Gemini** وأعددتها بنموذج `gemini-2.0-flash`.
> إن كنت تقصد **Gemma** فهي تعمل بنفس مفتاح Google — فقط غيّر اسم النموذج إلى `models/gemma-3-27b-it`.
> أخبرني إن أردت جعل Gemma هي الافتراضية.

## 🚀 خطوات التشغيل

### المرحلة 1 — احصل على مفتاح API

- **DeepSeek (موصى به افتراضيًا):** من https://platform.deepseek.com ← *API Keys* ← أنشئ مفتاحًا.
  (يلزم شحن رصيد بسيط جدًا.)
- **Google Gemini (بديل، به طبقة مجانية):** من https://aistudio.google.com/apikey ← أنشئ مفتاحًا.

> يكفيك واحد منهما للبدء. يمكنك إضافة الآخر لاحقًا والتبديل بنقرة.

### المرحلة 2 — n8n (العقل المنظّم)

1. شغّل n8n (أسهل طريقة عبر Docker):
   ```bash
   docker run -d --name n8n -p 5678:5678 \
     -e GENERIC_TIMEZONE="Asia/Baghdad" -e N8N_SECURE_COOKIE=false \
     -v n8n_data:/home/node/.n8n \
     -v "$(pwd)/knowledge:/data" \
     n8nio/n8n
   ```
   > ربط `knowledge/` بـ `/data` يجعل ملف المعرفة متاحًا داخل n8n على `/data/knowledge.md`.

2. افتح `http://<عنوان-الخادم>:5678` ثم **⋮ → Import from File** واستورد
   `n8n/masjid-whatsapp-workflow.json`.

3. **أضِف مفتاح API:**
   - افتح عقدة **DeepSeek (API)** → *Credential → Create New* → الصق مفتاح DeepSeek.
   - (اختياري) افتح عقدة **Gemini (API)** → *Credential → Create New* → الصق مفتاح Google.

4. في عقدة **Send WhatsApp Reply** اضبط **URL** ليشير إلى جسر Baileys (انظر جدول الشبكة أدناه).
   الافتراضي `http://localhost:3000/send`.

5. تأكّد أن مسار الملف في عقدة **Read Knowledge File** هو `/data/knowledge.md`
   (أو المسار الفعلي لملفك إن لم تستخدم Docker).

6. **فعّل التدفّق** (زر *Active*)، ثم انسخ رابط الـ Webhook الإنتاجي:
   `http://<عنوان-n8n>:5678/webhook/masjid-bot`

### المرحلة 3 — جسر Baileys (واتساب)

```bash
cd baileys-bridge
cp .env.example .env
#   عدّل .env: ضع N8N_WEBHOOK_URL = رابط Webhook من الخطوة السابقة
npm install
npm start
```

سيظهر **رمز QR** في الطرفية. من هاتف المسجد:
**واتساب ← الإعدادات ← الأجهزة المرتبطة ← ربط جهاز** ← امسح الرمز. ✅

> 💡 استخدم رقم واتساب مخصّصًا للمسجد، لأن الجهاز يُربط كجهاز مرتبط (Linked Device).

### المرحلة 4 — جرّب! 🎉

أرسل من أيّ هاتف إلى رقم المسجد: *«متى صلاة الجمعة؟»* — وانتظر الردّ بالعربية.

## 🔁 تبديل النموذج (DeepSeek ↔ Gemini)

في التدفّق توجد عقدتان: **DeepSeek (API)** موصولة افتراضيًا، و **Gemini (API)** بديلة.
للتبديل: احذف وصلة النموذج الحالي إلى **Generate Answer**، ثم اسحب وصلة من النموذج الآخر إليها.
(نموذج واحد فقط في كل مرّة — وهناك ملاحظة لاصقة في التدفّق تشرح ذلك.)

لاستخدام **Gemma** بدل Gemini: غيّر اسم النموذج في عقدة Gemini إلى `models/gemma-3-27b-it` (نفس مفتاح Google).

## 🌐 إعداد الشبكة (أهمّ نقطة — اقرأها إن لم يعمل /send)

عقدة **Send WhatsApp Reply** في n8n تنادي الجسر. القيمة الصحيحة للـ URL تعتمد على مكان التشغيل:

| n8n يعمل في… | الجسر يعمل في… | استخدم URL |
|---|---|---|
| نفس الجهاز (بدون Docker) | نفس الجهاز | `http://localhost:3000/send` |
| Docker | على نفس الجهاز (بدون Docker) | `http://host.docker.internal:3000/send` |
| Docker (نفس docker-compose) | Docker | `http://baileys:3000/send` |
| جهاز A | جهاز B (آخر) | `http://<عنوان-B>:3000/send` |

> على لينكس مع Docker، قد تحتاج لإضافة `--add-host=host.docker.internal:host-gateway` عند تشغيل n8n.

## ✏️ تعديل إجابات البوت = تعديل ملف `knowledge/knowledge.md`

- ضع كل معلومات مسجدك: المواقيت، الدروس، الخدمات، الأسئلة الشائعة… على شكل أسئلة/أجوبة.
- **البوت يجيب من هذا الملف فقط** ولا يخترع. إن لم تكن الإجابة موجودة، يحيل المصلّي إلى الإمام.
- بعد أي تعديل، تُحدَّث الإجابات تلقائيًا (الملف يُقرأ مع كل رسالة، لا حاجة لإعادة التشغيل).
- لاستخدام **PDF** بدل النص: في عقدة *Extract Text* غيّر *Operation* إلى **Extract from PDF**،
  واجعل *Read Knowledge File* يشير إلى ملف `.pdf`.

## 🔒 ملاحظات أمان وفقه

- البوت مضبوط ليجيب **بالعربية ومن الملف فقط**، ولا يُصدر فتاوى من عنده؛ المسائل الشرعية تُحال للإمام.
  (التعليمات مكتوبة داخل الـ prompt في عقدة *Generate Answer* — يمكنك تعديلها.)
- لحماية مسار `/send`: ضع `API_TOKEN` في `.env`، وأضف في عقدة n8n هيدر `x-api-token` بنفس القيمة.
- مجلد `baileys-bridge/auth_info` يحتوي جلسة واتساب، ومفاتيح API سرّية — **لا تشاركها ولا ترفعها على Git** (مستثناة أصلًا).

## 🛠️ حلّ المشكلات الشائعة

- **لا يصل ردّ:** تحقّق من URL في *Send WhatsApp Reply* (جدول الشبكة)، وجرّب `GET http://<host>:3000/health`.
- **خطأ مصادقة من النموذج (401):** تأكّد من صحّة مفتاح API ومن وجود رصيد (DeepSeek) أو تفعيل المفتاح (Google).
- **n8n لا يقرأ الملف:** تأكّد من ربط `-v .../knowledge:/data` وأن المسار `/data/knowledge.md`.
- **انقطاع واتساب باستمرار:** احذف `auth_info` وأعد مسح QR. استخدم رقمًا مخصّصًا للمسجد.
- **الردّ بطيء أو مطوّل:** تأكّد أنك على `deepseek-chat` (وليس `deepseek-reasoner`).

## 💻 بديل بلا إنترنت (Ollama على Mac mini M4) — اختياري

إن أردت تشغيلًا محليًا بالكامل بلا API ولا إنترنت:
1. ثبّت Ollama على الـ M4 ونزّل `qwen2.5:7b` أو `gemma3:12b`.
2. في n8n أضف عقدة **Ollama Chat Model** بدل DeepSeek/Gemini، ووصّلها بـ *Generate Answer*.
3. اضبط Base URL على عنوان الـ M4 + `:11434` (مع `OLLAMA_HOST=0.0.0.0` على الماك).

> الفرق: محلي = خصوصية تامّة ومجاني لكن جودة أقل قليلًا؛ API = جودة أعلى للعربية بتكلفة زهيدة.

## 🌟 تحسينات مستقبلية (اختياري)

- **الرسائل الصوتية:** تحويل الصوت إلى نص (Whisper) ليُجيب البوت على الأسئلة الصوتية.
- **ملف معرفة ضخم:** استبدال «حشو الملف في الطلب» بـ **بحث دلالي (RAG)** عبر قاعدة متجهات.
- **مواقيت تلقائية:** جلب مواقيت الصلاة من واجهة برمجية حسب مدينتك بدل كتابتها يدويًا.

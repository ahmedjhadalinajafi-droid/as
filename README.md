# 🕌 بوت أسئلة المسجد عبر واتساب — Masjid WhatsApp Q&A Bot

بوت يستقبل أسئلة المصلّين على **واتساب**، يقرأ السؤال، يبحث عن الإجابة في **ملفٍ تُحدِّده أنت**،
ثم يردّ **بالعربية** تلقائيًا.

**يندمج مع إعدادك الحالي:**
- **n8n** (الذي يعمل لديك مسبقًا) — لا نُشغّل واحدًا جديدًا.
- **جسر Baileys** (في هذا المستودع) — واتساب + تقديم ملف المعرفة عبر HTTP، على المنفذ **3100**.
- **DeepSeek / Gemini عبر مفتاح API** — للإجابة بالعربية.
- **لا نلمس Evolution API** إطلاقًا.

---

## المخطّط

```
  المصلّي (واتساب)
      │ (1) سؤال
      ▼
 ┌──────────────────────────┐   (2) Webhook   ┌───────────────────────────┐
 │   Baileys Bridge (3100)  │ ──────────────► │   n8n (الموجود لديك)      │
 │  • واتساب ↔ HTTP         │ ◄────────────── │  • يجلب /knowledge        │
 │  • GET /knowledge        │  (5) POST /send │  • يسأل DeepSeek/Gemini    │
 │  • POST /send            │ ◄── (3) GET ──  │                           │
 └──────────────────────────┘   /knowledge    └─────────────┬─────────────┘
      │ (6) يرسل الإجابة                                     │ (4) سؤال + مصدر
      ▼                                                      ▼
  المصلّي (واتساب)                                  DeepSeek API / Gemini API
```

كل المكوّنات تتخاطب عبر **عنوان خادمك (SERVER_IP)** والمنافذ المنشورة.

---

## ما تحتاجه

- n8n يعمل لديك (موجود) + Docker (موجود).
- **مفتاح API واحد** على الأقل:
  - **Gemini** (به طبقة مجانية): https://aistudio.google.com/apikey  ← المفتاح يبدأ بـ `AIza...`
  - أو **DeepSeek**: https://platform.deepseek.com
- **عنوان خادمك** في الشبكة: شغّل `hostname -I` وخذ أول عنوان (مثل `192.168.1.20`).

## خطوات التشغيل

### 1) عدّل ملف المعرفة
افتح `knowledge/knowledge.md` واملأه بمعلومات مسجدك (المواقيت، الدروس، الخدمات، الأسئلة الشائعة).
> الجسر يقرأ الملف طازجًا مع كل سؤال، فأي تعديل ينعكس فورًا (لا حاجة لإعادة التشغيل).

### 2) شغّل جسر Baileys (المنفذ 3100)
```bash
cd ~/as
docker compose up -d --build
docker compose logs -f          # سيظهر رمز QR
```
من **هاتف المسجد**: واتساب ← الإعدادات ← الأجهزة المرتبطة ← **ربط جهاز** ← امسح الرمز. ✅
> ملاحظة: هذا يربط الجسر كجهاز مرتبط. استخدم رقمًا مخصّصًا للمسجد.
> تحقّق من العمل: `curl http://localhost:3100/health`

### 3) استورد التدفّق في n8n الحالي
افتح n8n (`http://SERVER_IP:5678`) ← القائمة **⋮ → Import from File** ← اختر
`n8n/masjid-whatsapp-workflow.json`.

ثم عدّل **عنوان الخادم** في عقدتَين (استبدل `YOUR_SERVER_IP` بعنوانك من `hostname -I`):
- عقدة **Get Knowledge** → URL = `http://SERVER_IP:3100/knowledge`
- عقدة **Send WhatsApp Reply** → URL = `http://SERVER_IP:3100/send`

### 4) أضِف مفتاح API
- افتح عقدة **DeepSeek (API)** → *Credential → Create New* → الصق مفتاح DeepSeek.
- (أو) عقدة **Gemini (API)** → الصق مفتاح Google. (لجعل Gemini الافتراضي، انظر «تبديل النموذج».)

### 5) فعّل التدفّق
اضغط **Active** (أعلى اليمين). انسخ رابط الـ Webhook الإنتاجي إن أردت:
`http://SERVER_IP:5678/webhook/masjid-bot` (الجسر يستعمله تلقائيًا عبر host.docker.internal).

### 6) جرّب! 🎉
أرسل من أيّ هاتف إلى رقم المسجد: *«متى صلاة الجمعة؟»* — وانتظر الردّ بالعربية.

## 🧠 DeepSeek أم Gemini؟

| النموذج | الاسم في n8n | العربية | السعر |
|---|---|---|---|
| **DeepSeek** (الافتراضي) | `deepseek-chat` | ⭐⭐⭐⭐⭐ | رخيص جدًا (النموذج الكامل V3 عبر API) |
| **Gemini 3.5 Flash** (بديل) | `models/gemini-3.5-flash` | ⭐⭐⭐⭐⭐ | **به طبقة مجانية** (أحدث إصدار GA من عائلة Gemini 3) |

> ⚠️ استخدم `deepseek-chat` وليس `deepseek-reasoner` (الأخير بطيء ومُطوّل وغير مناسب لردود واتساب).
> 🔎 أسماء نماذج Gemini تتغيّر؛ خذ الاسم الدقيق من https://aistudio.google.com (قسم Models).
> لاستخدام **Gemma** بدل Gemini: غيّر اسم النموذج إلى `models/gemma-3-27b-it` (نفس مفتاح Google).

**التكلفة لمسجد؟ شبه معدومة** — الحجم قليل، و Gemini مجاني غالبًا، و DeepSeek من أرخص الواجهات.

### 🔁 تبديل النموذج
في التدفّق: عقدة **DeepSeek (API)** موصولة افتراضيًا، و **Gemini (API)** بديلة.
للتبديل: احذف وصلة النموذج الحالي إلى **Generate Answer**، ثم اسحب وصلة من النموذج الآخر إليها.
(نموذج واحد فقط في كل مرّة — هناك ملاحظة لاصقة في التدفّق تشرح ذلك.)

## 🌐 ملاحظات الشبكة (مهمّة)

- المنفذ **3100** للجسر (لأن `3000` مشغول لديك بـ openspeedtest).
- في n8n، عنوانا **Get Knowledge** و **Send WhatsApp Reply** يجب أن يستعملا **عنوان خادمك** `SERVER_IP:3100`
  (لأن n8n داخل حاوية لا تعرف `localhost` الجسر).
- الجسر ينادي n8n عبر `host.docker.internal:5678` (مضبوط في `docker-compose.yml` عبر `host-gateway`).
- إن لم يصل ردّ: جرّب `curl http://SERVER_IP:3100/health` ثم تحقّق من العنوانين في n8n.

---

## 🔒 أمان وفقه

- البوت مضبوط ليجيب **بالعربية ومن الملف فقط**، ولا يُصدر فتاوى؛ المسائل الشرعية تُحال للإمام
  (التعليمات داخل الـ prompt في عقدة *Generate Answer*).
- لحماية `/send`: ضع `API_TOKEN` في `baileys-bridge/.env` وأضف هيدر `x-api-token` في عقدة n8n.
- **لا تشارك مفاتيح API ولا مجلد `auth_info`** ولا ترفعها على Git (مستثناة أصلًا).

---

## 🛠️ مشاكل شائعة

- **لا يصل ردّ:** عنوان n8n خاطئ — تأكّد أنه `SERVER_IP:3100` وليس `localhost`. جرّب `/health`.
- **خطأ 401 من النموذج:** مفتاح API خاطئ أو بلا رصيد (DeepSeek) / غير مفعّل (Google).
- **`/knowledge` يرجع 404:** تأكّد أن `./knowledge/knowledge.md` موجود (مربوط في compose).
- **انقطاع واتساب:** احذف `baileys-bridge/auth_info` وأعد مسح QR.
- **تعارض المنفذ 3100:** غيّره في `docker-compose.yml` و`.env` وفي عنوانَي n8n.

# 🕌 بوت أسئلة المسجد عبر واتساب — Masjid WhatsApp Q&A Bot

بوت يستقبل أسئلة المصلّين على **واتساب**، يقرأ السؤال، يبحث عن الإجابة في **ملفٍ تُحدِّده أنت**،
ثم يردّ **بالعربية** تلقائيًا. كل ذلك يعمل على **خادمك الخاص** (بدون خدمات مدفوعة).

**التقنيات:** Baileys (واتساب) + n8n (التدفّق) + Ollama (الذكاء الاصطناعي محليًا).

---

## كيف يعمل؟ (المخطّط)

```
  المصلّي على واتساب
        │  (1) يرسل سؤالًا بالعربية
        ▼
 ┌─────────────────────┐     (2) Webhook      ┌──────────────────────────────┐
 │  Baileys Bridge     │ ───────────────────► │            n8n               │
 │  (baileys-bridge/)  │                      │  • يقرأ ملف المعرفة          │
 │   واتساب ↔ HTTP     │ ◄─────────────────── │  • يبني السؤال + المصدر       │
 └─────────────────────┘    (5) POST /send    │  • يسأل النموذج (Ollama)      │
        │                                      └──────────────┬───────────────┘
        │  (6) يرسل الإجابة                                    │ (3) سؤال + مصدر
        ▼                                                      ▼
  المصلّي على واتساب                                  ┌──────────────────┐
                                                       │  Ollama (M4)     │
                                          (4) إجابة ◄──│  Qwen2.5 عربي    │
                                                       └──────────────────┘
```

1. المصلّي يرسل سؤالًا على رقم واتساب المسجد.
2. جسر Baileys يحوّل الرسالة إلى n8n عبر Webhook.
3. n8n يقرأ ملف `knowledge.md` ويبني الطلب (السؤال + محتوى الملف كمصدر).
4. نموذج Ollama (يعمل على Mac mini M4) يُولّد الإجابة بالعربية **اعتمادًا على الملف فقط**.
5. n8n يرسل الإجابة إلى جسر Baileys عبر `POST /send`.
6. الجسر يرسلها إلى المصلّي على واتساب.

## 🧠 أيّ نموذج ذكاء اصطناعي؟ (لماذا Qwen2.5 وليس Gemma أو DeepSeek؟)

سؤال ممتاز. القاعدة هنا: نريد نموذجًا **يجيد العربية** + **سريع** + **يتّبع التعليمات بإيجاز** +
**يعمل فعليًا على Mac mini M4**. إليك المقارنة:

| النموذج | العربية | يعمل على M4؟ | ملاحظات |
|---|---|---|---|
| **Qwen2.5** (7B / 14B) | ⭐⭐⭐⭐⭐ | ✅ بسهولة | الأفضل لهذه المهمة: عربية قوية، سريع، يتّبع التعليمات. **الافتراضي.** |
| **Gemma 3** (4B / 12B / 27B) | ⭐⭐⭐⭐⭐ | ✅ (12B مناسب) | بديل ممتاز! يدعم 140+ لغة رسميًا وعربيته قويّة. **يمكنك استخدامه (تبديل بسطر واحد).** |
| **Gemma 2** (9B / 27B) | ⭐⭐⭐⭐ | ✅ | جيّد، لكنّ Gemma 3 أحدث وأفضل للعربية. |
| **DeepSeek-R1 / V3 (الكامل)** | ⭐⭐⭐ | ❌ مستحيل | حجمه 671B — يحتاج عتادًا ضخمًا، لا يعمل على M4 إطلاقًا. |
| **DeepSeek-R1 المقطّر** (7B/8B/14B) | ⭐⭐ | ✅ | مبنيّ على Qwen/Llama، لكنّه **نموذج تفكير**: بطيء ومُطوّل (`<think>...`) وغير مناسب لردود واتساب القصيرة، وعربيته أضعف. |

**الخلاصة:**
- ✅ **Qwen2.5** (الافتراضي) أو **Gemma 3** = الخياران الأفضل للعربية على جهازك.
- ❌ تجنّب **DeepSeek** لهذه المهمة تحديدًا: إمّا ضخم جدًا (لا يعمل محليًا)، أو نسخة تفكير بطيئة وعربيتها أضعف.

> 🔁 **التبديل سهل جدًا (سطر واحد):** غيّر اسم النموذج في خانة *Model* داخل عقدة Ollama في n8n،
> ثم نزّله بـ `ollama pull <model>`. لا شيء آخر يتغيّر في التدفّق. جرّب الاثنين واختر الأفضل لمسجدك.

نماذج جاهزة للتجربة:
```bash
ollama pull qwen2.5:7b      # الافتراضي (سريع، عربية قوية)
ollama pull qwen2.5:14b     # أدقّ، إن سمحت الذاكرة (≈ 16GB+)
ollama pull gemma3:12b      # بديل ممتاز للعربية
```

## 🚀 خطوات التشغيل

> **عتادك:** Mac mini M4 (للذكاء الاصطناعي — قويّ وسريع) + خادم i7-7700 (لـ n8n والجسر).
> **الأبسط:** شغّل كل شيء على الـ M4 (كله `localhost`). **البديل:** وزّعه كما هو موضّح أدناه.

### المرحلة 1 — Ollama على Mac mini M4 (الدماغ)

```bash
# 1) ثبّت Ollama من https://ollama.com  ثم نزّل النموذج:
ollama pull qwen2.5:7b

# 2) لكي يقبل Ollama الاتصال من الأجهزة الأخرى في الشبكة (إن كان n8n على جهاز آخر):
#    على الماك، اضبط المتغيّر ثم أعد تشغيل Ollama:
launchctl setenv OLLAMA_HOST "0.0.0.0:11434"
#    (أو شغّله يدويًا:  OLLAMA_HOST=0.0.0.0 ollama serve )

# 3) اعرف عنوان الـ M4 في الشبكة (ستحتاجه في n8n):
ipconfig getifaddr en0      # مثال: 192.168.1.50
```

### المرحلة 2 — n8n (العقل المنظّم)

1. شغّل n8n (أسهل طريقة عبر Docker على خادم i7-7700):
   ```bash
   docker run -d --name n8n -p 5678:5678 \
     -e GENERIC_TIMEZONE="Asia/Baghdad" -e N8N_SECURE_COOKIE=false \
     -v n8n_data:/home/node/.n8n \
     -v "$(pwd)/knowledge:/data" \
     n8nio/n8n
   ```
   > ربط `knowledge/` بـ `/data` يجعل ملف المعرفة متاحًا داخل n8n على `/data/knowledge.md`.

2. افتح `http://<عنوان-الخادم>:5678` ثم: **⋮ → Import from File** واستورد
   `n8n/masjid-whatsapp-workflow.json`.

3. **أنشئ بيانات اعتماد Ollama:** افتح عقدة **Qwen2.5 (Ollama)** → *Credential* → *Create New* →
   ضع **Base URL** = `http://<عنوان-M4>:11434` (مثال: `http://192.168.1.50:11434`).
   إن كان كل شيء على الـ M4 نفسه، استخدم `http://localhost:11434`.

4. في عقدة **Send WhatsApp Reply** عدّل **URL** ليشير إلى جسر Baileys (انظر جدول الشبكة أدناه).
   الافتراضي `http://localhost:3000/send`.

5. تأكّد أن مسار الملف في عقدة **Read Knowledge File** هو `/data/knowledge.md`
   (أو المسار الفعلي لملفك إن لم تستخدم Docker).

6. **فعّل التدفّق** (زر *Active*)، ثم انسخ رابط الـ Webhook الإنتاجي:
   `http://<عنوان-n8n>:5678/webhook/masjid-bot`

### المرحلة 3 — جسر Baileys (واتساب)

```bash
cd baileys-bridge
cp .env.example .env
#   عدّل .env: ضع N8N_WEBHOOK_URL = رابط Webhook من الخطوة السابقة
npm install
npm start
```

سيظهر **رمز QR** في الطرفية. من هاتف المسجد:
**واتساب ← الإعدادات ← الأجهزة المرتبطة ← ربط جهاز** ← امسح الرمز. ✅

> 💡 استخدم رقم واتساب مخصّصًا للمسجد (يفضّل WhatsApp على رقم منفصل)، لأن الجهاز يُربط كجهاز مرتبط.

### المرحلة 4 — جرّب! 🎉

أرسل من أيّ هاتف إلى رقم المسجد: *«متى صلاة الجمعة؟»* — وانتظر الردّ بالعربية.

## 🌐 إعداد الشبكة (أهمّ نقطة — اقرأها إن لم يعمل /send)

عقدة **Send WhatsApp Reply** في n8n تنادي الجسر. القيمة الصحيحة للـ URL تعتمد على مكان التشغيل:

| n8n يعمل في… | الجسر يعمل في… | استخدم URL |
|---|---|---|
| نفس الجهاز (بدون Docker) | نفس الجهاز | `http://localhost:3000/send` |
| Docker | على نفس الجهاز (بدون Docker) | `http://host.docker.internal:3000/send` |
| Docker (نفس docker-compose) | Docker | `http://baileys:3000/send` |
| جهاز A | جهاز B (آخر) | `http://<عنوان-B>:3000/send` |

> على لينكس مع Docker، قد تحتاج لإضافة `--add-host=host.docker.internal:host-gateway` عند تشغيل n8n.

بالمثل، **Base URL** الخاص بـ Ollama = عنوان جهاز الـ M4 + `:11434`.

## ✏️ تعديل إجابات البوت = تعديل ملف `knowledge/knowledge.md`

- ضع كل معلومات مسجدك: المواقيت، الدروس، الخدمات، الأسئلة الشائعة… على شكل أسئلة/أجوبة.
- **البوت يجيب من هذا الملف فقط** ولا يخترع. إن لم تكن الإجابة موجودة، يحيل المصلّي إلى الإمام.
- بعد أي تعديل، تُحدَّث الإجابات تلقائيًا (الملف يُقرأ مع كل رسالة، لا حاجة لإعادة التشغيل).
- صيغة الملف يمكن أن تكون أيّ نصّ. لاستخدام **PDF** بدلًا من ذلك: في عقدة *Extract Text* غيّر
  *Operation* إلى **Extract from PDF**، واجعل *Read Knowledge File* يشير إلى ملف `.pdf`.

## 🔒 ملاحظات أمان وفقه

- البوت مضبوط ليجيب **بالعربية ومن الملف فقط**، ولا يُصدر فتاوى من عنده؛ المسائل الشرعية تُحال للإمام.
  (هذه التعليمات مكتوبة داخل الـ prompt في عقدة *Generate Answer* — يمكنك تعديلها.)
- لحماية مسار `/send`: ضع `API_TOKEN` في `.env`، وأضف في عقدة n8n هيدر `x-api-token` بنفس القيمة.
- مجلد `baileys-bridge/auth_info` يحتوي جلسة واتساب — **لا تشاركه ولا ترفعه على Git** (مستثنى أصلًا).

## 🛠️ حلّ المشكلات الشائعة

- **لا يصل ردّ:** تحقّق من URL في *Send WhatsApp Reply* (جدول الشبكة)، وجرّب `GET http://<host>:3000/health`.
- **n8n لا يقرأ الملف:** تأكّد من ربط `-v .../knowledge:/data` وأن المسار `/data/knowledge.md`.
- **خطأ اتصال Ollama:** تأكّد أن `OLLAMA_HOST=0.0.0.0` على الـ M4، وأن جدار الحماية يسمح بالمنفذ 11434.
- **انقطاع واتساب باستمرار:** احذف `auth_info` وأعد مسح QR. استخدم رقمًا مخصّصًا للمسجد.
- **الردّ بطيء:** جرّب `qwen2.5:7b` (أسرع) بدل 14B، وخفّض حجم ملف المعرفة.

## 🌟 تحسينات مستقبلية (اختياري)

- **الرسائل الصوتية:** إضافة تحويل الصوت إلى نص (Whisper) ليُجيب البوت على الأسئلة الصوتية.
- **ملف معرفة ضخم:** استبدال «حشو الملف في الطلب» بـ **بحث دلالي (RAG)** عبر قاعدة متجهات.
- **مواقيت تلقائية:** ربط عقدة تجلب مواقيت الصلاة من واجهة برمجية حسب مدينتك بدل كتابتها يدويًا.
